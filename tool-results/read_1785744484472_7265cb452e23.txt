     1→# Phase 9 — Admin Panel
     2→
     3→## HotHoosh Enterprise Admin Panel — Complete Design Specification
     4→
     5→---
     6→
     7→## 9.1 Overview
     8→
     9→### 9.1.1 Purpose
    10→
    11→The HotHoosh Admin Panel is the centralized management console for platform operators and organization administrators. It provides full visibility and control over every dimension of the platform: users, organizational hierarchies, AI agents, knowledge infrastructure, API integrations, billing, security, and system health. Every entity that exists in the HotHoosh ecosystem is observable, configurable, and auditable from this panel.
    12→
    13→The admin panel is not a secondary feature bolted onto the main application. It is a first-class citizen of the architecture, sharing the same design system, component library, and RTL foundation as the user-facing workspace — but with its own layout paradigm, navigation model, and permission boundary. Admin users operate within a dedicated layout that prioritizes data density, batch operations, and cross-tenant visibility over the conversational, content-focused layout of the standard workspace.
    14→
    15→### 9.1.2 Design Principles
    16→
    17→| Principle | Description |
    18→|-----------|-------------|
    19→| **Persian-First RTL** | Every admin page renders RTL by default. All layouts, tables, forms, and data visualizations use CSS logical properties. No physical direction properties (`left`, `right`, `padding-left`) are used anywhere. |
    20→| **Glass Enterprise** | The admin panel extends the core Glass Morphism design system with elevated data-density variants. Tables, stat cards, and dashboards use `glass-panel-elevated` and `glass-panel-data` surface tokens. |
    21→| **Action-Oriented** | Every list page leads to a clear primary action (create, edit, configure). Every detail page exposes contextual actions inline. No dead-end pages. |
    22→| **Audit-First** | Every mutation operation through the admin panel generates an audit log entry. Admins can see who changed what, when, and from where. |
    23→| **Multi-Tenant Aware** | Super admins see all organizations. Org admins see their org and all children. Workspace admins see only their workspace. The UI adapts its scope controls accordingly. |
    24→| **Progressive Disclosure** | Summary dashboards show high-level KPIs. Drill-down pages reveal granular data. Inline expanders reveal related entities without navigation. |
    25→| **Batch Operations** | List views support multi-select with bulk actions (delete, reassign, export, change status). Selection persists across pagination. |
    26→
    27→### 9.1.3 Access Control Matrix
    28→
    29→The admin panel is gated by a dedicated permission namespace: `admin:*`. Access is determined by the intersection of the user's role hierarchy and the tenant scope they operate within.
    30→
    31→| Role | Scope | Access Level |
    32→|------|-------|-------------|
    33→| **Super Admin** | All organizations | Full CRUD on all entities. System settings. Billing. Audit logs. |
    34→| **Org Admin** | Own organization + descendants | Full CRUD on users, companies, brands, workspaces, agents within org scope. Read-only on billing. No system settings. |
    35→| **Company Admin** | Own company + descendants | CRUD on users, brands, workspaces, agents within company scope. Read-only on org-level settings. |
    36→| **Brand Admin** | Own brand + workspaces | CRUD on users, workspaces, agents within brand scope. |
    37→| **Workspace Admin** | Own workspace | CRUD on workspace users, agents, knowledge, memory packs. |
    38→
    39→Permission checks are enforced at two levels: **route-level** (middleware guards prevent navigation to unauthorized pages) and **component-level** (UI elements are conditionally rendered based on granular permissions like `admin:users:create`, `admin:billing:read`).

    43→## 9.2 Admin Layout Architecture
    44→
    45→### 9.2.1 Shell Structure
    46→
    47→The admin panel uses a dedicated root layout (`/admin/layout.tsx`) that is completely separate from the main workspace layout. This ensures no CSS or state leakage between the two paradigms.
    48→
    49→```
    50→┌─────────────────────────────────────────────────────────────┐
    51→│  Top Bar (fixed, h-14, glass-panel-solid)                   │
    52→│  [Logo] [Tenant Scope Selector] [Search] [Notifications] [User Menu] │
    53→├──────────┬──────────────────────────────────────────────────┤
    54→│ Sidebar  │  Main Content Area                               │
    55→│ (w-64,   │  (scrollable, p-6)                               │
    56→│  fixed,  │                                                  │
    57→│  glass-  │  ┌──────────────────────────────────────────┐    │
    58→│  panel-  │  │  Breadcrumb Trail                         │    │
    59→│  solid)  │  ├──────────────────────────────────────────┤    │
    60→│          │  │  Page Header + Actions                    │    │
    61→│          │  ├──────────────────────────────────────────┤    │
    62→│  [Nav    │  │                                          │    │
    63→│   Items] │  │  Page Content                             │    │
    64→│          │  │  (tables, forms, dashboards)              │    │
    65→│          │  │                                          │    │
    66→│          │  │                                          │    │
    67→│          │  └──────────────────────────────────────────┘    │
    68→├──────────┴──────────────────────────────────────────────────┤
    69→│  (no footer — content extends to bottom)                    │
    70→└─────────────────────────────────────────────────────────────┘
    71→```
    72→
    73→### 9.2.2 Top Bar Components
    74→
    75→| Component | Description |
    76→|-----------|-------------|
    77→| **Logo** | HotHoosh logo mark + wordmark. Links to `/admin/dashboard`. Clicking in non-super-admin context shows the current org name as a subtitle. |
    78→| **Tenant Scope Selector** | A dropdown/combobox that filters all admin data to the selected tenant level. Options: `همه سازمان‌ها` (All Orgs), then each org/company/brand the user has admin access to. Changing scope reloads all data tables with the new tenant filter. |
    79→| **Global Search** | Command-K powered search across all admin entities. Results grouped by entity type. Keyboard navigable. Shows recent searches. |
    80→| **Notifications** | Bell icon with unread count badge. Dropdown shows system alerts (failed jobs, quota breaches, new org signups). |
    81→| **User Menu** | Avatar + name. Dropdown: Profile, Preferences (theme toggle), Keyboard Shortcuts, Logout. Super admins see an additional "Enter Workspace" link to switch to the standard app. |
    82→
    83→### 9.2.3 Sidebar Navigation
    84→
    85→The sidebar uses a grouped navigation model with collapsible sections. Icons use the Phosphor icon set with RTL mirror support. Active state uses the `accent` color token with a `start` border indicator (logical property: `border-inline-start`).
    86→
    87→```
    88→● داشبورد (Dashboard)
    89→
    90→━━ مدیریت کاربران (User Management) ━━
    91→  ○ کاربران (Users)
    92→  ○ نقش‌ها و دسترسی‌ها (Roles & Permissions)
    93→
    94→━━ ساختار سازمانی (Org Structure) ━━
    95→  ○ سازمان‌ها (Organizations)
    96→  ○ شرکت‌ها (Companies)
    97→  ○ برندها (Brands)
    98→
    99→━━ هوش مصنوعی (AI) ━━
   100→  ○ عوامل هوشمند (Agents)
   101→  ○ بسته‌های حافظه (Memory Packs)
   102→  ○ دانش (Knowledge)
   103→  ○ تأمین‌کنندگان API (API Providers)
   104→  ○ مدل‌ها (Models)
   105→
   106→━━ عملیات (Operations) ━━
   107→  ○ مصرف منابع (Usage)
   108→  ○ صورتحساب (Billing)
   109→  ○ لاگ‌های ممیزی (Audit Logs)
   110→  ○ لاگ‌های سیستم (System Logs)
   111→
   112→━━ تنظیمات (Settings) ━━
   113→  ○ تنظیمات عمومی (General Settings)
   114→  ○ تنظیمات امنیتی (Security Settings)
   115→```
   116→
   117→Navigation items are permission-gated. If a user lacks `admin:users:read`, the entire "User Management" group is hidden. Group headers collapse when all children are hidden, preventing orphaned section titles.
   118→
   119→### 9.2.4 Breadcrumb Trail
   120→
   121→Every admin page renders a breadcrumb trail below the top bar. The breadcrumb is constructed from the route segment hierarchy:
   122→
   123→```
   124→مدیریت > سازمان‌ها > [نام سازمان] > ویرایش
   125→Admin  > Orgs       > [Org Name]   > Edit
   126→```
   127→
   128→The first segment is always "مدیریت" (Admin) and links to `/admin/dashboard`. Each subsequent segment maps to its parent route. The final segment is the current page title and is not a link. Breadcrumbs are generated automatically from the route tree using a `useBreadcrumbs()` hook that reads metadata from `layout.tsx` or `page.tsx` exports.

   132→## 9.3 Dashboard Page
   133→
   134→**Route**: `/admin/dashboard`
   135→**Permission**: `admin:dashboard:read`
   136→**Layout**: Full-width, no sidebar content panel.
   137→
   138→### 9.3.1 Purpose
   139→
   140→The admin dashboard is the operational command center. It provides a real-time overview of platform health, resource consumption, growth metrics, and actionable alerts. Every KPI card is a drill-down entry point that navigates to the corresponding detailed page.
   141→
   142→### 9.3.2 KPI Summary Row
   143→
   144→A horizontal row of 6 stat cards, each using the `glass-panel-data` surface token. Cards are equal-width on desktop, 2-column on tablet, stacked on mobile. Each card contains:
   145→
   146→- **Icon** (Phosphor, 24px, accent color)
   147→- **Label** (caption-sm, muted color)
   148→- **Value** (heading-2xl, primary color)
   149→- **Trend indicator** (badge: `↑ ۱۲٪` in green or `↓ ۳٪` in red, compared to previous period)
   150→- **Click target**: Entire card is clickable, navigates to the relevant detail page.
   151→
   152→| Card | Metric | Source | Drill-down Target |
   153→|------|--------|--------|-------------------|
   154→| کاربران فعال (Active Users) | Users with at least 1 session in last 30 days | `users` table | `/admin/users?status=active` |
   155→| سازمان‌ها (Organizations) | Total org count | `organizations` table | `/admin/organizations` |
   156→| مکالمات امروز (Conversations Today) | Chat sessions created today | `chat_sessions` table | `/admin/usage?tab=conversations` |
   157→| مصرف توکن (Token Usage) | Total tokens consumed this month | Aggregated from `usage_logs` | `/admin/usage?tab=tokens` |
   158→| عوامل فعال (Active Agents) | Agents with `status = active` | `agents` table | `/admin/agents?status=active` |
   159→| درآمد ماهانه (Monthly Revenue) | Current billing cycle revenue | `invoices` table | `/admin/billing` |
   160→
   161→### 9.3.3 Charts Row
   162→
   163→Two charts side by side (60/40 split on desktop, stacked on mobile):
   164→
   165→**Token Consumption Trend** (60%)
   166→- Type: Area chart (ECharts)
   167→- X-axis: Last 30 days, daily granularity
   168→- Y-axis: Token count (formatted with Persian numerals and "هزار" / "میلیون" suffixes)
   169→- Two series: Input tokens (filled area, accent-light) and Output tokens (filled area, accent-dark)
   170→- Interaction: Hover shows tooltip with exact values. Click on a day navigates to `/admin/usage?date=YYYY-MM-DD`.
   171→- Data source: TanStack Query hook `useTokenTrend({ range: '30d' })`
   172→
   173→**Usage by Model Distribution** (40%)
   174→- Type: Donut chart (ECharts)
   175→- Segments: Top 5 models by usage, remainder grouped as "سایر" (Other)
   176→- Center text: Total token count for the period
   177→- Interaction: Click on a segment filters the token trend chart to that model only.
   178→- Data source: TanStack Query hook `useModelDistribution({ range: '30d' })`
   179→
   180→### 9.3.4 Recent Activity Feed
   181→
   182→A vertical timeline of the 20 most recent significant events across the platform. Each entry shows:
   183→
   184→- **Timestamp** (relative: "۲ ساعت پیش", Solar Hijri on hover)
   185→- **Actor** (user avatar + display name, linked to user detail)
   186→- **Action** (verb in Persian: "ایجاد کرد", "ویرایش کرد", "حذف کرد")
   187→- **Target** (entity type icon + name, linked to entity detail)
   188→- **Context badge** (org/company name, muted)
   189→
   190→Events included: user created/deleted, org created, agent deployed, knowledge base uploaded, billing event, permission change. Data source: Audit log stream, polled every 30 seconds via TanStack Query with `refetchInterval: 30000`.
   191→
   192→### 9.3.5 System Health Bar
   193→
   194→A slim horizontal bar at the bottom of the dashboard showing 4 system health indicators as colored dots with labels:
   195→
   196→| Indicator | Health Check | Green | Yellow | Red |
   197→|-----------|-------------|-------|--------|-----|
   198→| API Gateway | Response time < 200ms | < 200ms | 200-500ms | > 500ms |
   199→| Database | Connection pool utilization | < 70% | 70-90% | > 90% |
   200→| Queue System | BullMQ backlog count | < 100 | 100-1000 | > 1000 |
   201→| Vector Store | pgvector query latency | < 50ms | 50-150ms | > 150ms |
   202→
   203→Each dot is a clickable link that expands to show a 5-minute response time sparkline and current numeric values.

   207→## 9.4 Users Page
   208→
   209→**Route**: `/admin/users`
   210→**Permission**: `admin:users:read` (list), `admin:users:create` (create), `admin:users:update` (edit), `admin:users:delete` (delete)
   211→**Layout**: List page with filters, search, and bulk actions.
   212→
   213→### 9.4.1 Purpose
   214→
   215→The users page is the primary interface for managing all user accounts across the platform. It supports searching, filtering, sorting, bulk operations, and individual user management. For super admins, this shows all users across all organizations. For org admins, it shows users within their org scope.
   216→
   217→### 9.4.2 Filter Bar
   218→
   219→A horizontal filter bar with the following controls, all using shadcn components styled with the Glass Enterprise theme:
   220→
   221→| Filter | Type | Options |
   222→|--------|------|---------|
   223→| جستجو (Search) | Search input | Searches across: display_name, email, phone_number. Debounced 300ms. |
   224→| وضعیت (Status) | Multi-select combobox | فعال (Active), غیرفعال (Inactive), معلق (Suspended), در انتظار (Pending) |
   225→| نقش (Role) | Multi-select combobox | Dynamically populated from `roles` table within current scope |
   226→| سازمان (Organization) | Combobox | Populated based on tenant scope. Super admins see all orgs. |
   227→| تاریخ ثبت‌نام (Registration Date) | Date range picker | Solar Hijri calendar. Uses `DatePickerRange` component. |
   228→| آخرین ورود (Last Login) | Date range picker | Solar Hijri calendar. |
   229→
   230→Filters are URL-search-param driven. Changing any filter updates the URL without full-page navigation (Next.js `useRouter().replace()` with `shallow: true`). Filters persist across page navigation within the users section. A "پاک کردن فیلترها" (Clear Filters) button resets all filters to defaults.
   231→
   232→### 9.4.3 Data Table
   233→
   234→A full-featured data table built on TanStack Table with the following columns:
   235→
   236→| Column | Width | Content | Sortable | Description |
   237→|--------|-------|---------|----------|-------------|
   238→| ☐ (Checkbox) | 40px | Checkbox for row selection | No | Supports select-all on current page. Header checkbox shows indeterminate state when some rows selected. |
   239→| آواتار + نام (Avatar + Name) | flex | User avatar (32px, rounded-full) + display_name (body-md, primary) + email (caption-sm, muted) | Yes (by name) | Avatar uses initials fallback. Name links to user detail page. |
   240→| سازمان (Organization) | 150px | Organization name badge | Yes | Shows org name. If user belongs to multiple orgs, shows primary org + "+N" badge. |
   241→| نقش (Role) | 120px | Role badge (colored by role level) | Yes | Org Admin = amber, Company Admin = blue, Brand Admin = purple, Workspace Admin = green, Member = gray. |
   242→| وضعیت (Status) | 100px | Status dot + label | Yes | Active = green dot, Inactive = gray, Suspended = red, Pending = yellow. |
   243→| آخرین ورود (Last Login) | 130px | Relative timestamp ("۲ روز پیش") + absolute on hover | Yes | "هرگز" (Never) if no login recorded. |
   244→| تاریخ ثبت‌نام (Created) | 120px | Solar Hijri date | Yes | Formatted: "۱۴۰۵/۰۵/۱۱" |
   245→| عملیات (Actions) | 80px | Icon buttons: View, Edit, More (dropdown) | No | More dropdown: Suspend, Delete, Reset Password, Impersonate (super admin only). |
   246→
   247→**Pagination**: Bottom of table. Shows "نمایش ۱-۲۰ از ۱,۲۳۴ کاربر" (Showing 1-20 of 1,234 users). Page size selector: 10, 20, 50, 100. Previous/Next buttons with Persian labels.
   248→
   249→**Empty State**: When no users match filters, shows a centered illustration (Phosphor `users` icon, large, muted) with the text "کاربری با این فیلترها یافت نشد" (No users found with these filters) and a "پاک کردن فیلترها" (Clear Filters) button.
   250→
   251→### 9.4.4 Bulk Actions Bar
   252→
   253→When one or more rows are selected, a fixed bar slides up from the bottom of the table showing:
   254→
   255→- Selection count: "۳ کاربر انتخاب شده" (3 users selected)
   256→- Action buttons: تغییر نقش (Change Role), تعلیق (Suspend), حذف (Delete), خروجی CSV (Export CSV)
   257→- Clear selection button (X icon)
   258→
   259→Bulk actions open a confirmation dialog before execution. Delete shows a warning dialog with the count. Role change opens a dialog with a role selector dropdown. Export triggers a server-side CSV generation job and shows a toast notification when the file is ready for download.
   260→
   261→### 9.4.5 User Detail Page
   262→
   263→**Route**: `/admin/users/[userId]`
   264→**Layout**: Two-column layout (60/40 split). Main column shows user profile and activity. Side column shows related entities.
   265→
   266→**Main Column — Profile Card**:
   267→- Large avatar (80px) with upload capability (admin can set user avatar)
   268→- Display name (editable inline on double-click)
   269→- Email (with verified badge if confirmed)
   270→- Phone number (with verified badge)
   271→- Role badge + organization badge
   272→- Status badge with toggle switch
   273→- Created date (Solar Hijri, full format with time)
   274→- Last login (IP address + user agent summary)
   275→
   276→**Main Column — Activity Timeline**:
   277→- Paginated list of the user's recent actions from audit logs
   278→- Each entry: timestamp, action type icon, action description, target entity link
   279→- Filterable by action type (login, create, update, delete, chat)
   280→
   281→**Side Column — Memberships**:
   282→- List of org/company/brand/workspace memberships
   283→- Each entry: entity name, role, joined date, status
   284→- "افزودن به سازمان" (Add to Organization) button opens a dialog
   285→
   286→**Side Column — Usage Summary** (collapsible):
   287→- Token usage this month (bar chart, last 30 days)
   288→- Total conversations count
   289→- Active agents used
   290→- Knowledge bases accessed
   291→
   292→**Side Column — Sessions** (collapsible):
   293→- Active sessions list with device, IP, last activity
   294→- "پایان تمام نشست‌ها" (Terminate All Sessions) button (requires confirmation)
   295→
   296→### 9.4.6 Create/Edit User Dialog
   297→
   298→A slide-over panel (400px width, from the start edge in RTL) with form fields:
   299→
   300→| Field | Type | Validation |
   301→|-------|------|------------|
   302→| نام نمایشی (Display Name) | Text input | Required, 3-100 characters |
   303→| ایمیل (Email) | Email input | Required, unique, valid email format |
   304→| شماره تلفن (Phone) | Tel input | Optional, Iranian mobile format validation (09xxxxxxxxx) |
   305→| رمز عبور (Password) | Password input (create only) | Required on create, min 8 chars, must include uppercase, lowercase, number, special char. Strength meter shown below. |
   306→| سازمان (Organization) | Combobox | Required. Scoped to admin's accessible orgs. |
   307→| نقش (Role) | Select | Required. Roles available depend on selected organization. |
   308→| وضعیت (Status) | Toggle | Active/Inactive. Default: Active. |
   309→
   310→Form submission triggers server-side validation, user creation/update, and audit log entry. On success, the dialog closes, the table refreshes, and a success toast appears.

   381→
   382→**Route**: `/admin/companies`
   383→**Permission**: `admin:companies:read`, `admin:companies:create`, `admin:companies:update`, `admin:companies:delete`
   384→**Layout**: List page.
   385→

   707→### 9.10.5 Document Upload Flow
   708→
   709→1. User clicks "آپلود اسناد" (Upload Documents) or drags files onto the upload zone
   710→2. A dialog opens with a drag-and-drop area and a file list
   711→3. Files are validated client-side: type check, size check (max 50MB per file), duplicate check
   712→4. Files are uploaded to pre-signed S3 URLs (direct upload, not proxied through server)
   713→5. After upload, each file enters a processing queue. Status updates via SSE:
   714→   - `uploaded` → `extracting` → `chunking` → `embedding` → `indexed` → `ready`
   715→   - Or `failed` with error reason
   716→6. The document list updates in real-time as each file progresses through the pipeline
   717→7. Failed documents show an error icon with a retry button and error detail expansion

  1280→## 9.18 System Logs Page
  1281→
  1282→**Route**: `/admin/logs`
  1283→**Permission**: `admin:system-logs:read`
  1284→**Layout**: Full-width log viewer with real-time streaming.
  1285→
  1286→### 9.18.1 Purpose
  1287→
  1288→Technical system logs for platform operators. Unlike audit logs (which record user actions), system logs capture application-level events: errors, warnings, info messages from all backend services. This page is primarily used by DevOps and engineering teams for debugging and monitoring.
  1289→
  1290→### 9.18.2 Log Stream Controls
  1291→
  1292→| Control | Description |
  1293→|---------|-------------|
  1294→| **جریان زنده (Live Stream)** | Toggle to enable real-time log streaming via SSE. When enabled, new log entries appear at the top of the list as they arrive. Auto-scroll toggle available. |
  1295→| **مکث (Pause)** | Pause the stream to inspect current logs without new entries pushing content. |
  1296→| **فیلتر سطح (Level Filter)** | Multi-select: DEBUG, INFO, WARN, ERROR, FATAL. Default: WARN + ERROR. |
  1297→| **فیلتر سرویس (Service Filter)** | Multi-select: api-gateway, auth-service, llm-router, context-engine, rag-engine, memory-engine, tool-engine, streaming-engine, queue-worker, scheduler. |
  1298→| **جستجو (Search)** | Text input with debounce. Searches log message content. Supports simple wildcards. |
  1299→| **بازه زمانی (Time Range)** | Preset: Last 15min, 1h, 6h, 24h, 7d. Custom range with datetime pickers. |
  1300→
  1301→### 9.18.3 Log Entries
  1302→
  1303→Each log entry is rendered as a single-line row with expandable detail:
  1304→
  1305→- **Timestamp**: ISO 8601 with milliseconds ("2025-08-02T14:30:00.123Z") + relative time ("۳۰ ثانیه پیش")
  1306→- **Level**: Color-coded badge: DEBUG=gray, INFO=blue, WARN=amber, ERROR=red, FATAL=purple (with pulsing animation)
  1307→- **Service**: Service name badge
  1308→- **Message**: Log message (truncated to 200 chars in row view, full text in expanded view)
  1309→- **Expand**: Click to show full message, stack trace (for ERROR/FATAL), request ID, trace ID, metadata key-value pairs
  1310→
  1311→**Error entries** (ERROR and FATAL) are visually emphasized: red-tinted row background, bold message text. These can be filtered to show only errors using the level filter.
  1312→
  1313→### 9.18.4 Log Detail Panel
  1314→
  1315→Expanding a log entry reveals:
  1316→
  1317→- **Full message**: Untruncated log message with syntax highlighting for stack traces
  1318→- **Context**: Request ID, trace ID, session ID (if available)
  1319→- **Metadata**: Key-value pairs attached to the log entry (e.g., `user_id`, `org_id`, `model`, `latency_ms`)
  1320→- **Stack trace** (ERROR/FATAL only): Formatted, syntax-highlighted stack trace with clickable file paths
  1321→- **Related logs**: Button to search for other logs with the same request ID or trace ID
  1322→- **Copy button**: Copy full log entry as JSON
  1323→
  1324→### 9.18.5 Log Analytics Panel
  1325→
  1326→A collapsible analytics panel at the top of the page (toggle via "تحلیل‌ها" button) shows:
  1327→
  1328→- **Error rate trend**: 24-hour line chart of error rate (errors/minute)
  1329→- **Error distribution by service**: Donut chart
  1330→- **Top error messages**: List of top 10 most frequent error messages with count and trend (increasing/decreasing/stable)
  1331→- **Latency percentiles**: P50/P95/P99 across all services, 24-hour trend

  1652→## 9.22 Responsive Behavior
  1653→
  1654→The admin panel follows a desktop-first design philosophy (admin panels are primarily used on desktop/laptop screens) but remains fully functional on tablets and mobile devices.
  1655→
  1656→### 9.22.1 Breakpoints
  1657→
  1658→| Breakpoint | Width | Layout Behavior |
  1659→|-----------|-------|----------------|
  1660→| **Desktop XL** | >= 1440px | Full layout: 256px sidebar + content. Tables show all columns. |
  1661→| **Desktop** | 1024-1439px | Sidebar collapses to icon-only mode (64px width) with tooltip labels. Tables hide less-important columns. |
  1662→| **Tablet** | 768-1023px | Sidebar becomes a hamburger menu (off-canvas drawer). Tables switch to card layout on mobile. Filter bar collapses to toggle. |
  1663→| **Mobile** | < 768px | No persistent sidebar. Navigation via hamburger menu. Tables render as stacked cards. Slide-over panels become full-screen. Charts stack vertically. |
  1664→
  1665→### 9.22.2 Sidebar Responsive Behavior
  1666→
  1667→- **Desktop XL**: Full sidebar with icons + labels. Group headers visible.
  1668→- **Desktop**: Icon-only sidebar. Hovering an icon shows a tooltip with the label. Group headers become thin dividers.
  1669→- **Tablet/Mobile**: Sidebar hidden. A hamburger button in the top bar opens the sidebar as an off-canvas drawer with overlay. Drawer is dismissible by clicking outside or pressing Escape.
  1670→
  1671→### 9.22.3 Table Responsive Behavior
  1672→
  1673→- **Desktop**: Full table with all columns visible. Horizontal scroll if columns exceed viewport.
  1674→- **Tablet**: Less-important columns are hidden via `columnVisibility`. A column picker button in the table header allows showing/hiding columns.
  1675→- **Mobile**: Table rows transform into stacked card layout. Each "card" shows the primary column (name/avatar) as the header, followed by key-value pairs for the remaining columns. Actions move to a bottom sheet on row tap.
  1676→
  1677→### 9.22.4 Chart Responsive Behavior
  1678→
  1679→- **Desktop**: Charts render at their specified dimensions with full interactivity.
  1680→- **Tablet**: Charts reduce padding and font sizes. Tooltips remain full-size.
  1681→- **Mobile**: Charts stack vertically (no side-by-side). Touch interactions enabled (pinch to zoom on time-series charts). Legend moves below the chart.

  1685→## 9.23 State Management for Admin Panel
  1686→
  1687→### 9.23.1 Zustand Stores
  1688→
  1689→The admin panel uses dedicated Zustand stores, separate from the main workspace stores. Each major domain has its own store slice:
  1690→
  1691→| Store | State | Actions |
  1692→|-------|-------|---------|
  1693→| `useAdminFilterStore` | Active filters per page, sort settings, view mode (list/grid) | `setFilter(page, key, value)`, `clearFilters(page)`, `setSort(page, column, direction)`, `setViewMode(page, mode)` |
  1694→| `useAdminSelectionStore` | Selected row IDs per table, selection mode (none/single/multi) | `selectRow(page, id)`, `deselectRow(page, id)`, `selectAll(page, ids)`, `clearSelection(page)` |
  1695→| `useAdminTenantScopeStore` | Current tenant scope (org/company/brand ID), scope level | `setScope(level, id)`, `resetScope()` |
  1696→| `useAdminSidebarStore` | Sidebar collapsed state, active group, mobile drawer open | `toggleCollapse()`, `setActiveGroup(group)`, `openMobileDrawer()`, `closeMobileDrawer()` |
  1697→| `useAdminSettingsStore` | Unsaved settings changes per section, dirty state | `updateSetting(section, key, value)`, `discardChanges(section)`, `markSaved(section)` |
  1698→
  1699→### 9.23.2 TanStack Query Keys
  1700→
  1701→All admin data fetching uses TanStack Query with a structured key factory:
  1702→
  1703→```
  1704→adminKeys:
  1705→  users:       { list: [filters], detail: [userId] }
  1706→  orgs:        { list: [filters], detail: [orgId] }
  1707→  companies:   { list: [filters], detail: [companyId] }
  1708→  brands:      { list: [filters], detail: [brandId] }
  1709→  agents:      { list: [filters], detail: [agentId] }
  1710→  memory:      { list: [filters], detail: [memoryPackId] }
  1711→  knowledge:   { list: [filters], detail: [knowledgeBaseId] }
  1712→  providers:   { list: [], detail: [providerId] }
  1713→  models:      { list: [], detail: [modelId] }
  1714→  usage:       { overview: [range, scope], tokens: [range, scope], ... }
  1715→  audit:       { list: [filters] }
  1716→  billing:     { overview: [], invoices: [filters], ... }
  1717→  roles:       { list: [], detail: [roleId] }
  1718→  settings:    { section: [sectionName] }
  1719→  dashboard:   { kpis: [scope], charts: [range, scope] }
  1720→```
  1721→
  1722→### 9.23.3 Cache Invalidation Strategy
  1723→
  1724→Mutations through the admin panel follow a structured cache invalidation pattern:
  1725→
  1726→- **Create**: Invalidate the `list` query for the corresponding entity. Optimistically prepend to the list (with a temporary ID) and roll back on error.
  1727→- **Update**: Invalidate both the `detail` query (for the specific entity) and the `list` query. Optimistically update the detail cache.
  1728→- **Delete**: Invalidate the `list` query. Optimistically remove from the list cache. On error, re-insert.
  1729→- **Bulk delete**: Invalidate the `list` query. Show a loading overlay on the table during the mutation.
  1730→- **Settings update**: Invalidate the specific `settings` section query. Show a toast on success.
  1731→
  1732→All mutations that modify data also trigger a refetch of the dashboard KPIs if the user navigates back to the dashboard, ensuring metrics reflect the latest state.

  1736→## 9.24 Toast Notification System
  1737→
  1738→The admin panel uses a toast notification system for operation feedback. Toasts appear in the bottom-start corner (bottom-right in LTR) and stack vertically.
  1739→
  1740→| Variant | Icon | Use Case |
  1741→|---------|------|----------|
  1742→| `success` | Check-circle (green) | Entity created, updated, deleted successfully. Settings saved. |
  1743→| `error` | X-circle (red) | Mutation failed. Validation error. Network error. |
  1744→| `warning` | Alert-triangle (amber) | Operation succeeded with warnings. Approaching quota limit. |
  1745→| `info` | Info (blue) | Background operation started (export, reprocess). Non-critical informational message. |
  1746→
  1747→Toast properties:
  1748→- **Auto-dismiss**: 5 seconds for success/info, 10 seconds for warning, no auto-dismiss for error (requires manual dismiss).
  1749→- **Action button**: Optional. E.g., "بررسی" (Review) on error toasts that link to the error detail.
  1750→- **Undo**: Available on delete toasts. "بازگردانی" (Undo) button that calls the restore API.
  1751→- **Progress**: For long-running operations, a progress bar within the toast shows completion percentage.
  1752→- **Stack limit**: Maximum 5 visible toasts. Older toasts are dismissed when the limit is exceeded.
