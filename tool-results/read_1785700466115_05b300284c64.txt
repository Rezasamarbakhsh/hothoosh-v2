     1→# UI System — HotHoosh Enterprise AI Workspace
     2→
     3→---
     4→
     5→## 1. Design Philosophy
     6→
     7→### 1.1 Minimal Glass Enterprise
     8→
     9→HotHoosh follows a **Minimal Glass Enterprise** aesthetic — a design language that merges glass morphism with the data-density demands of enterprise software. The visual identity communicates professionalism, clarity, and depth without visual clutter.
    10→
    11→Core characteristics:
    12→
    13→| Characteristic | Description |
    14→|----------------|-------------|
    15→| **Glass surfaces** | Translucent panels with `backdrop-filter: blur()` create a layered, dimensional UI. Depth is communicated through opacity and blur, not through heavy shadows or borders. |
    16→| **Enterprise data density** | Despite the glass aesthetic, information is never sacrificed for decoration. Tables, dashboards, and forms present dense data with clear hierarchy and scannable structure. |
    17→| **Persian-first, RTL-native** | The entire interface is built RTL-first. Persian (فارسی) is the default language. English is a secondary option. CSS logical properties are mandatory — no physical direction properties. |
    18→| **Depth hierarchy** | Four glass surface tiers (`glass-panel-solid`, `glass-panel-elevated`, `glass-panel-data`, `glass-panel-subtle`) create a clear visual stack: structural chrome → elevated content → data surfaces → interactive states. |
    19→| **Minimal decoration** | No gratuitous gradients, no decorative illustrations in core UI, no unnecessary borders. Content is the focus. |
    20→| **Dark/light parity** | Both themes are first-class citizens. Neither theme is an afterthought. All color pairings in dark mode meet the same WCAG contrast requirements as light mode. |
    21→
    22→### 1.2 Guiding Principles
    23→
    24→1. **Content over chrome** — UI elements serve content, never compete with it.
    25→2. **Consistency over cleverness** — Predictable patterns beat novel interactions.
    26→3. **Accessibility over aesthetics** — If a visual treatment fails contrast, it is removed.
    27→4. **Performance over polish** — Animations and effects must not degrade rendering performance.
    28→5. **Tokens over values** — Every color, size, and spacing value is a design token. Hardcoded values are forbidden.

   120→### 2.7 Dark Mode Switching Mechanism
   121→
   122→Dark mode is implemented by re-declaring all CSS variables under the `[data-theme="dark"]` selector. The `data-theme` attribute is set on the `<html>` element.
   123→
   124→```css
   125→:root {
   126→  --color-primary-500: #6366f1;
   127→  --color-text-primary: #0f172a;
   128→  --color-background: #f8fafc;
   129→  /* ... all light mode tokens */
   130→}
   131→
   132→[data-theme="dark"] {
   133→  --color-primary-500: #818cf8;
   134→  --color-text-primary: #f1f5f9;
   135→  --color-background: #0d0d14;
   136→  /* ... all dark mode tokens */
   137→}
   138→```
   139→
   140→Tailwind's `dark:` variant is **never used**. All theme-aware styling references CSS variables via `var(--color-*)`. See §10 for full implementation details.

   240→## 6. Design Tokens — Shadows
   241→
   242→HotHoosh's glass morphism aesthetic relies on `backdrop-filter: blur()` for depth rather than heavy box-shadows. Shadows are used sparingly and only for elements that need to float above glass surfaces (dropdowns, popovers, tooltips).
   243→
   244→### 6.1 Shadow Scale
   245→
   246→| CSS Variable | Light Mode | Dark Mode | Usage |
   247→|--------------|------------|-----------|-------|
   248→| `--shadow-xs` | `0 1px 2px rgba(0, 0, 0, 0.04)` | `0 1px 2px rgba(0, 0, 0, 0.20)` | Minimal elevation: subtle cards. |
   249→| `--shadow-sm` | `0 1px 3px rgba(0, 0, 0, 0.06), 0 1px 2px rgba(0, 0, 0, 0.04)` | `0 1px 3px rgba(0, 0, 0, 0.30), 0 1px 2px rgba(0, 0, 0, 0.20)` | Small elevation: dropdowns, popovers. |
   250→| `--shadow-md` | `0 4px 6px rgba(0, 0, 0, 0.05), 0 2px 4px rgba(0, 0, 0, 0.04)` | `0 4px 6px rgba(0, 0, 0, 0.35), 0 2px 4px rgba(0, 0, 0, 0.25)` | Medium elevation: slide-overs, command palette. |
   251→| `--shadow-lg` | `0 10px 15px rgba(0, 0, 0, 0.06), 0 4px 6px rgba(0, 0, 0, 0.04)` | `0 10px 15px rgba(0, 0, 0, 0.40), 0 4px 6px rgba(0, 0, 0, 0.30)` | High elevation: modals, dialogs. |
   252→| `--shadow-xl` | `0 20px 25px rgba(0, 0, 0, 0.06), 0 8px 10px rgba(0, 0, 0, 0.04)` | `0 20px 25px rgba(0, 0, 0, 0.45), 0 8px 10px rgba(0, 0, 0, 0.35)` | Maximum elevation: fullscreen overlays. |
   253→
   254→### 6.2 Glass Depth Rule
   255→
   256→Glass panels **do not** use `box-shadow` for depth. Depth is achieved exclusively through:
   257→
   258→1. **Opacity differential** — more opaque surfaces appear closer to the viewer.
   259→2. **Backdrop blur** — higher blur values increase perceived distance from the background.
   260→3. **Border** — a subtle `1px solid` border with `--color-border-default` separates glass layers.
   261→
   262→Shadows are reserved for elements that must appear to "float" above all glass surfaces: dropdown menus, tooltip popovers, modal overlays, and the command palette.

   266→## 7. Design Tokens — Glass Surfaces
   267→
   268→The four glass surface types form the backbone of the visual hierarchy. Each tier has a defined background opacity, blur value, and border treatment.
   269→
   270→### 7.1 glass-panel-solid
   271→
   272→**Highest opacity.** Used for structural chrome that must feel anchored and permanent.
   273→
   274→| Property | Light Mode | Dark Mode |
   275→|----------|------------|-----------|
   276→| Background | `var(--color-surface-solid)` → `rgba(255, 255, 255, 0.92)` | `var(--color-surface-solid)` → `rgba(17, 17, 27, 0.95)` |
   277→| Backdrop Filter | `blur(16px) saturate(180%)` | `blur(16px) saturate(180%)` |
   278→| Border | `1px solid var(--color-border-default)` | `1px solid var(--color-border-default)` |
   279→| Shadow | `none` | `none` |
   280→
   281→**Usage:** Sidebars (workspace and admin), top bars, bottom navigation bars, fixed structural panels.
   282→
   283→```css
   284→.glass-panel-solid {
   285→  background: var(--color-surface-solid);
   286→  backdrop-filter: blur(16px) saturate(180%);
   287→  -webkit-backdrop-filter: blur(16px) saturate(180%);
   288→  border: 1px solid var(--color-border-default);
   289→}
   290→```
   291→
   292→### 7.2 glass-panel-elevated
   293→
   294→**Medium opacity.** Used for content containers that float above the page background but below structural chrome.
   295→
   296→| Property | Light Mode | Dark Mode |
   297→|----------|------------|-----------|
   298→| Background | `var(--color-surface-elevated)` → `rgba(255, 255, 255, 0.80)` | `var(--color-surface-elevated)` → `rgba(30, 30, 46, 0.85)` |
   299→| Backdrop Filter | `blur(12px) saturate(160%)` | `blur(12px) saturate(160%)` |
   300→| Border | `1px solid var(--color-border-default)` | `1px solid var(--color-border-default)` |
   301→| Shadow | `none` | `none` |
   302→
   303→**Usage:** Cards, modals, slide-over panels, dialog containers, form sections, chat panels.
   304→
   305→```css
   306→.glass-panel-elevated {
   307→  background: var(--color-surface-elevated);
   308→  backdrop-filter: blur(12px) saturate(160%);
   309→  -webkit-backdrop-filter: blur(12px) saturate(160%);
   310→  border: 1px solid var(--color-border-default);
   311→  border-radius: var(--radius-lg);
   312→}
   313→```

   362→## 8. Design Tokens — Animation
   363→
   364→### 8.1 Duration Scale
   365→
   366→| CSS Variable | Value | Usage |
   367→|--------------|-------|-------|
   368→| `--duration-75` | `75ms` | Micro-interactions: hover color change, toggle switch, checkbox fill. |
   369→| `--duration-150` | `150ms` | Small transitions: button press, tooltip appear, badge pulse. |
   370→| `--duration-200` | `200ms` | Standard transitions: slide-over open/close, filter bar expand. |
   371→| `--duration-300` | `300ms` | Medium transitions: modal open/close, page transitions, tab content switch. |
   372→| `--duration-500` | `500ms` | Large transitions: complex layout changes, multi-element staggered reveals. |
   373→
   374→### 8.2 Easing Functions
   375→
   376→| CSS Variable | Value | Usage |
   377→|--------------|-------|-------|
   378→| `--ease-out` | `cubic-bezier(0.0, 0.0, 0.2, 1)` | Elements entering the viewport or appearing. |
   379→| `--ease-in-out` | `cubic-bezier(0.4, 0.0, 0.2, 1)` | State changes that reverse (hover in/out, toggle). |
   380→| `--ease-spring` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | Playful, bouncy interactions: toast entrance, notification badge pop. |
   381→
   382→### 8.3 Animation Rules
   383→
   384→| Rule | Description |
   385→|------|-------------|
   386→| Only animate `transform` and `opacity` | Animating layout properties (`width`, `height`, `top`, `margin`, `padding`) causes layout reflow. This is forbidden per Engineering Rules §10.1.4. |
   387→| Use `will-change` sparingly | Apply `will-change: transform, opacity` only to elements that are currently animating, and remove it when the animation completes. |
   388→| Respect `prefers-reduced-motion` | When `prefers-reduced-motion: reduce` is active, all transitions and animations are disabled. State changes are instant. |
   389→| Stagger with delay, not duration | When animating multiple elements in sequence, use `transition-delay` increments (not different durations) to maintain visual consistency. |
   390→
   391→### 8.4 Reduced Motion
   392→
   393→```css
   394→@media (prefers-reduced-motion: reduce) {
   395→  *,
   396→  *::before,
   397→  *::after {
   398→    animation-duration: 0.01ms !important;
   399→    animation-iteration-count: 1 !important;
   400→    transition-duration: 0.01ms !important;
   401→    scroll-behavior: auto !important;
   402→  }
   403→}
   404→```
   405→
   406→This is the only context where `!important` is permitted (per Engineering Rules §10.1.4 exception).

   510→## 10. Dark Mode Implementation
   511→
   512→### 10.1 Mechanism
   513→
   514→Dark mode is implemented exclusively through **CSS variable switching** on the `<html>` element. The `data-theme` attribute controls which set of variable values is active.
   515→
   516→```html
   517→<html lang="fa" dir="rtl" data-theme="dark">
   518→```
   519→
   520→```css
   521→/* Light mode (default) */
   522→:root {
   523→  --color-primary-500: #6366f1;
   524→  --color-text-primary: #0f172a;
   525→  --color-background: #f8fafc;
   526→  --color-surface-solid: rgba(255, 255, 255, 0.92);
   527→  /* ... all light tokens */
   528→}
   529→
   530→/* Dark mode */
   531→[data-theme="dark"] {
   532→  --color-primary-500: #818cf8;
   533→  --color-text-primary: #f1f5f9;
   534→  --color-background: #0d0d14;
   535→  --color-surface-solid: rgba(17, 17, 27, 0.95);
   536→  /* ... all dark tokens */
   537→}
   538→```
   539→
   540→### 10.2 Rules
   541→
   542→| Rule | Description |
   543→|------|-------------|
   544→| No Tailwind `dark:` variant | Tailwind's class-based dark mode is forbidden. All theme-aware values use `var(--color-*)`. This is non-negotiable per Engineering Rules §10.1.4. |
   545→| No hardcoded colors | Hex, rgb, hsl values are forbidden. The only exceptions are `transparent` and `currentColor`. |
   546→| Variable-only references | Components reference tokens, never raw values: `background: var(--color-surface-elevated)`, not `background: rgba(255,255,255,0.8)`. |
   547→| Tailwind for layout only | Layout (flex, grid, spacing, sizing) uses Tailwind utilities. Colors, shadows, and effects use design token CSS variables via `var()`. |
   548→
   549→### 10.3 Theme Toggle Component
   550→
   551→| Prop | Type | Description |
   552→|------|------|-------------|
   553→| `theme` | `'light' \| 'dark' \| 'system'` | Current theme selection. |
   554→| `onThemeChange` | `(theme: ThemePreference) => void` | Callback when user selects a theme. |
   555→
   556→The toggle offers three options: light (☀️), dark (🌙), and system (follows OS preference). The icon-only toggle cycles through the three states on click. An expanded popover shows all three options with labels.
   557→
   558→### 10.4 System Preference Detection
   559→
   560→On initial load (and on change), the app detects the OS preference via `window.matchMedia('(prefers-color-scheme: dark)')`:
   561→
   562→1. If the user has an explicit preference stored (`theme` in user preferences API), use it.
   563→2. If no stored preference, follow the system preference.
   564→3. If system preference changes and user has not set an explicit preference, follow the new system preference.
   565→4. If user has set an explicit preference, system changes are ignored.
   566→
   567→### 10.5 Persistence
   568→
   569→Theme preference is stored per-user in the backend API (`PATCH /users/me/preferences { theme: 'dark' }`). On login, the preference is fetched and applied before the first render to prevent flash-of-wrong-theme (FOWT). The value is also cached in `localStorage` as a fallback for offline/reduced-functionality scenarios.

   639→## 12. Accessibility Standards
   640→
   641→All user-facing features meet **WCAG 2.2 Level AA** compliance. This is a requirement, not a goal.
   642→
   643→### 12.1 Semantic HTML
   644→
   645→| Rule | Description |
   646→|------|-------------|
   647→| Correct elements | Use `<button>` for actions, `<a>` for navigation, `<nav>` for navigation landmarks, `<main>` for main content, `<aside>` for complementary content. |
   648→| No div/span for interaction | Never use `<div>` or `<span>` with `onClick` for interactive elements. Use the correct semantic element. |
   649→| Landmarks | Every page has `<header>`, `<main>`, and (where applicable) `<nav>` and `<aside>` landmarks. |
   650→| Headings | Proper heading hierarchy (`h1` → `h2` → `h3`). Never skip levels. Each page has exactly one `h1`. |
   651→
   652→### 12.2 Focus Indicators
   653→
   654→| Requirement | Standard |
   655→|-------------|----------|
   656→| Default focus | Never use `outline: none` without a visible replacement. |
   657→| Custom focus ring | Minimum `2px` offset, `3:1` contrast against adjacent background. |
   658→| Focus visible | Use `:focus-visible` (not `:focus`) so keyboard users see the ring but mouse users do not. |
   659→| Focus management — modals | When a dialog opens, focus moves to the first focusable element inside the dialog. When it closes, focus returns to the trigger. |
   660→| Focus management — pages | On navigation, focus moves to the page heading or a skip-link target. |
   661→| Focus trap | Modals, slide-overs, and command palette trap focus within their container. Tab does not escape. |
   662→
   663→### 12.3 Color Contrast
   664→
   665→| Context | Minimum Ratio |
   666→|---------|---------------|
   667→| Normal text (< 18px, < 14px bold) | **4.5:1** against background |
   668→| Large text (≥ 18px, ≥ 14px bold) | **3:1** against background |
   669→| Non-text UI components (borders, icons, form controls) | **3:1** against adjacent color |
   670→| Focus indicators | **3:1** against background |
   671→| Dark mode | Same requirements as light mode. Dark mode is not an afterthought. |
   672→
   673→No information is conveyed by color alone. Status indicators always include text labels or icons in addition to color (e.g., a green dot + "فعال" text, not just a green dot).
   674→
   675→### 12.4 Touch Targets
   676→
   677→| Context | Minimum Size |
   678→|---------|--------------|
   679→| All interactive elements on mobile | **44 × 44px** minimum |
   680→| Dense data table rows | Expand the tap target with padding to meet 44px, even if the visible element is smaller. |
   681→| Inline links within text | Minimum 44px height tap area via line-height or padding. |
   682→| Icon-only buttons | 44 × 44px container, even if the icon is 16px or 24px. |
   683→
   684→### 12.5 Screen Reader Support
   685→
   686→| Requirement | Implementation |
   687→|-------------|---------------|
   688→| `alt` text | All images have descriptive `alt` text in the user's current language (Persian by default). |
   689→| Icon-only buttons | Every icon-only button has `aria-label` in Persian (e.g., `aria-label="بستن"` for close). |
   690→| Dynamic content | Chat messages, toast notifications, and real-time status updates use `aria-live="polite"` (or `"assertive"` for critical errors). |
   691→| Loading states | Loading states exceeding 3 seconds announce status via `aria-live`: "در حال بارگذاری..." (Loading...). |
   692→| Dialog roles | Modals use `role="dialog"`, `aria-modal="true"`, `aria-labelledby` (pointing to the dialog title). |
   693→| Tab interfaces | Use `role="tablist"`, `role="tab" with `aria-selected`, `role="tabpanel" with `aria-labelledby`. |
   694→| Data tables | Use `<table>` with proper `<thead>`, `<th scope="col">`, and `<caption>`. |
   695→| Language declaration | `<html lang="fa" dir="rtl">` for Persian. Switches to `lang="en" dir="ltr"` for English. |
   696→
   697→### 12.6 Keyboard Navigation
   698→
   699→| Requirement | Standard |
   700→|-------------|----------|
   701→| All interactive elements | Reachable and operable via keyboard (Tab, Shift+Tab, Enter, Space, Arrow keys, Escape). |
   702→| Tab order | Follows the visual/logical order of the page (top-to-bottom, start-to-end in RTL). |
   703→| Skip link | A "skip to content" link is the first focusable element on every page. Visible on focus only. |
   704→| Command palette | `Cmd+K` / `Ctrl+K` opens the global command palette. Arrow keys navigate, Enter selects, Escape closes. |
   705→| Dropdown menus | Arrow keys navigate items. Enter selects. Escape closes. Focus returns to trigger. |
   706→| Dialogs | Escape closes. Tab cycles through focusable elements within the dialog. |
   707→| Checkboxes and toggles | Space key toggles state. |
   708→| Radio groups | Arrow keys move between options. |
   709→
   710→### 12.7 Reduced Motion
   711→
   712→| Requirement | Implementation |
   713→|-------------|---------------|
   714→| `prefers-reduced-motion: reduce` | All transitions and animations are disabled. State changes are instant. |
   715→| Loading indicators | Replace animated spinners with static "در حال بارگذاری..." text or a static progress bar. |
   716→| Streaming indicator | Replace animated dots with static "در حال تولید پاسخ..." text. |
   717→| Auto-scroll | Chat auto-scroll still works (no animation to disable) but does not use smooth scrolling. |
