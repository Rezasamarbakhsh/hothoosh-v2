     7→     7→     7→## 1. Database Engine
     8→     8→     8→
     9→     9→     9→**PostgreSQL 16+** with the following extensions:
    10→    10→    10→
    11→    11→    11→| Extension | Version | Purpose |
    12→    12→    12→|-----------|---------|--------|
    13→    13→    13→| `uuid-ossp` | 1.1 | UUID v7 generation (via custom function) |
    14→    14→    14→| `vector` (pgvector) | 0.7+ | Vector embeddings storage and HNSW indexing |
    15→    15→    15→| `pg_trgm` | 1.6 | Trigram similarity for fuzzy text search |
    16→    16→    16→| `btree_gin` | 1.3 | GIN indexes on JSONB columns |
    17→    17→    17→
    18→    18→    18→### 1.1 UUID v7 Strategy
    19→    19→    19→
    20→    20→    20→HotHoosh uses **UUID v7** (time-sortable) as the default primary key for all entities. UUID v7 combines a Unix timestamp (millisecond precision) with random bytes, producing IDs that are:
    21→    21→    21→
    22→    22→    22→- **Globally unique** (no coordination needed)
    23→    23→    23→- **Time-sortable** (recent entities have higher IDs, benefiting B-tree indexes)
    24→    24→    24→- **K-sortable** within the same millisecond
    25→    25→    25→
    26→    26→    26→For **high-throughput append-only tables** (audit_logs, usage_logs, chat_messages, system_logs), **BIGINT** auto-increment is used instead to avoid UUID storage overhead and maintain maximum insert throughput.
    27→    27→    27→
    28→    28→    28→### 1.2 Migration Strategy
    29→    29→    29→
    30→    30→    30→Migrations are managed via a dedicated migration tool integrated with NestJS. Each migration file is timestamped and contains `UP` and `DOWN` functions. Migrations are:
    31→    31→    31→
    32→    32→    32→- **Sequential**: Each migration builds on the previous one.
    33→    33→    33→- **Irreversible by default**: `DOWN` functions must be explicitly written for rollback support.
    34→    34→    34→- **Tested**: Every migration is tested against a copy of production data before deployment.
    35→    35→    35→- **Reviewed**: Schema changes require PR review with at least 2 approvals.
    36→    36→    36→

   124→   124→   124→**Indexes:**
   125→   125→   125→- `uniq_orgs_slug` UNIQUE (slug) WHERE deleted_at IS NULL
   126→   126→   126→- `idx_orgs_owner_id` B-tree (owner_id)
   127→   127→   127→- `idx_orgs_plan_id` B-tree (plan_id)
   128→   128→   128→- `idx_orgs_status` B-tree (status) WHERE deleted_at IS NULL

   130→   130→   130→
   131→   131→   131→**RLS Policy:**
   132→   132→   132→- Super admins: full access
   133→   133→   133→- Org admins: access to own org + no access to others
   134→   134→   134→- Others: no direct access (access via company/brand/workspace membership)
